# ブラウザー動作確認チェックリスト

対象バージョン: v0.2.0 ｜ [説明書の目次へ](README.md)

このチェックリストは、配布ZIPを実際のWindows PCで開き、利用開始前に主要な操作を一巡するためのものです。各項目は「このように操作する」と「こうなれば正常」を対にしています。

すべてにチェックが付き、途中で画面が固まる、赤いエラーが出る、入力が消えるといった問題がなければ、そのPC・ブラウザーでの基本動作は良好と判断できます。

## 確認前の準備

実運用中のデータを使わず、確認専用の架空データで行ってください。すでに同じブラウザー・同じURLで本ツールを使っている場合は、先に「設定・バックアップ」からJSONをエクスポートします。

- [ ] GitHub Releasesからダウンロードした `parallel-work-time.zip` を、新しいフォルダーへ「すべて展開」した。
- [ ] 展開先に `start-local.cmd`、`local-settings.txt`、`README.md`、`manual` フォルダー、`アプリ内部（変更しないでください）` フォルダーがある。
- [ ] 実在する案件名・氏名・機密情報を入力しないことを確認した。
- [ ] すでに利用中のデータがある場合は、JSONバックアップを別の場所へ保存した。

このチェックリストは、保存データが無い初回状態から始めることを前提にしています（第1章のサンプルテンプレート3件、第2章の設定既定値など）。すでに同じURLで本ツールを利用中の場合は、確認用に新しいブラウザープロファイル（またはゲストウィンドウ）を作って行うと、実データに触れずに初回状態から確認できます。

対応をうたうブラウザー（Chrome・Edge・Firefox）で公開前確認を行う場合は、ブラウザーごとにこのチェックリストを1周し、それぞれ記録を残します。

## 1. 起動する

1. 展開したフォルダーの `start-local.cmd` をダブルクリックします。
2. 黒い画面を閉じずに待ちます。

正常なら、次の状態になります。

- [ ] 黒い画面にエラーが表示されず、ブラウザーが自動的に開く。
- [ ] ページ上部に「同時並行作業時間計測支援ツール」と表示される。
- [ ] 初回起動では、作業テンプレート画面に架空のサンプルテンプレートが3件表示される。
- [ ] 画面下部にスキーマ版が表示され、起動エラーの通知がない。

ブラウザーが自動で開かない場合でも、黒い画面に表示されたURLをブラウザーへ入力して開ければ、結果を備考へ記録して先へ進めます。

## 2. 画面を切り替える

ヘッダーの「案件・実施回」「集計・転記」「テンプレート」「アーカイブ」「設定」を順番に押します。

- [ ] 押した画面へ切り替わり、白紙や読込中のままにならない。
- [ ] 「案件・実施回」へ戻ると、左側に「新規案件」が表示される。
- [ ] 「設定」で保持期間30日、未終了しきい値12時間が表示される。

## 3. 案件と実施回を作る

1. 「案件・実施回」→「新規案件」を押します。
2. 次の架空データを入力して「登録」を押します。

   | 項目 | 入力例 |
   | ---- | ------ |
   | 案件ID | `PJ-SMOKE-001` |
   | 対象種別 | `対象種別A` |
   | バリエーション | `標準` |
   | 総予定数 | `10` |

3. 開いた実施回追加フォームで、作業日は今日、今回数量は `2` とし、作業項目を変更せず「作成」を押します。

正常なら、次の状態になります。

- [ ] 左ツリーへ `PJ-SMOKE-001` が表示される。
- [ ] 案件詳細に累計2、残数8と分かる表示がある。
- [ ] 第1回の実施回が作られ、テンプレート由来の作業項目が表示される。
- [ ] 画面下部に「保存しました」と表示される。

## 4. 開始・参加者変更・休憩・再開・終了を試す

作業項目を1つ選び、短時間で次の順に操作します。日時の初期値はそのままで構いません。

1. 「開始」を押し、架空の参加者 `テスト太郎` と `テスト花子` を追加して確定します。
2. 「参加者変更」を押し、`テスト花子` を外して `テスト太郎` だけで確定します。
3. 「休憩」を押して確定します。
4. 「再開」を押し、`テスト太郎` を指定して確定します。
5. 「終了」を押して確定します。

操作の途中と終了後を確認します。

- [ ] 開始後は状態が「作業中」になり、画面上部に未終了区間の警告が1件表示される。
- [ ] 警告内のリンクを押すと、該当する作業項目へ移動する。
- [ ] 参加者変更、休憩、再開のたびに、それまでの区間が閉じて新しい区間が作られる。
- [ ] 休憩後は状態が「休憩中」になり、操作が「再開」「終了」に変わる。
- [ ] 終了後は状態が「完了」になり、未終了区間の警告が消える。
- [ ] 作業項目詳細の履歴に、作業・休憩・作業の区間と参加者の変化が残る。

> この章の操作は数秒間隔で行うため、各区間の工数は「0分」と表示されます。分単位の計算は次章で確かめます。

## 5. 計算結果が分かる入力を作る

前章とは別の作業項目を開き、次の記録を追加します。日付は実施回の作業日と同じ日にしてください。

1. 「区間追加」を押し、作業区間を10時00分～10時40分、参加者を `テスト太郎` 1名として保存します。
2. 「直接入力」を押し、20分、参加者 `テスト太郎`、備考 `動作確認用の計測漏れ` として保存します。

- [ ] 区間による工数が40分と表示される。
- [ ] 直接入力が20分と表示される。
- [ ] その作業項目の転記値が60分になる。
- [ ] ブラウザーを再読み込みしても、追加した区間と直接入力が残る。

> 直接入力は参加者数を掛けない「すでに合計した工数」です。ここでは計算を分かりやすくするため1名にしています。

## 6. 未終了のまま集計できないことを確かめる

1. まだ使っていない作業項目で「開始」を押し、`テスト太郎` 1名で確定します。
2. 終了せず、ヘッダーの「集計・転記」を開きます。

- [ ] 開始した作業項目の転記値が「未確定」と表示される。
- [ ] 実施回を「集計済み」にできず、未終了区間を終える必要があると分かる。

「案件・実施回」へ戻ってその作業項目を終了し、もう一度「集計・転記」を開きます。

- [ ] 「未確定」が消え、「集計済みにする」を実行できる。

## 7. 集計・コピー・転記済みを試す

1. 「集計済みにする」を押します。
2. 「転記値をコピー」を押し、メモ帳などへ貼り付けます。
3. 「実施回を転記済みにする」を押します。

- [ ] 状態が「作業中」から「集計済み」、さらに「転記済み」へ変わる。
- [ ] メモ帳へタブ区切りの外部項目コードと転記値を貼り付けられる。
- [ ] 転記済みになると、作業区間や直接入力を追加・変更できない。

「転記済み状態を解除する」を押し、理由 `動作確認のため` を入力して解除します。

- [ ] 理由なしでは取り消せず、理由を入れると「集計済み」へ戻る。

確認後、もう一度転記済みにします。

## 8. アーカイブを試す

「集計・転記」で「アーカイブへ移す」を押し、ヘッダーの「アーカイブ」を開きます。

- [ ] 対象の実施回が通常の左ツリーから消える。
- [ ] アーカイブ画面に `PJ-SMOKE-001` の実施回が表示される。
- [ ] アーカイブ直後は保持期間が残っており、完全削除できない。
- [ ] ブラウザーを再読み込みしてもアーカイブ状態が残る。

この確認では完全削除を行う必要はありません。

## 9. JSONバックアップと復元を試す

1. 「設定」→「JSONをエクスポート」を押します。
2. ダウンロードされたJSONを、分かる場所へ保存します。
3. 「案件・実施回」で、確認用の別案件を登録します（案件ID `PJ-SMOKE-TEMP`、対象種別 `対象種別A`、バリエーション `標準`、総予定数 `10`。実施回は作らなくて構いません）。
4. 「設定」へ戻り、「取り込むJSONファイル」で手順2のJSONを選びます。
5. 「現在のデータを退避して取り込む」を選びます。

- [ ] ファイル名が `parallel-work-time_年月日-時分秒.json` の形で、0バイトではない。
- [ ] エクスポート後、設定画面に最終エクスポート日時が表示される。
- [ ] インポート時に「全置換」であることの確認が表示される。
- [ ] 取り込み前の退避JSONもダウンロードされる。
- [ ] 取り込み後は `PJ-SMOKE-TEMP` が消え、エクスポート時点の `PJ-SMOKE-001` とアーカイブ状態が復元される。
- [ ] ブラウザーを再読み込みしても復元結果が残る。

## 10. 終了と再起動を試す

1. ブラウザーのタブを閉じます。
2. 起動時に開いた黒い画面を閉じます。
3. もう一度 `start-local.cmd` をダブルクリックします。

- [ ] 同じURLでブラウザーが開く。
- [ ] 再起動後も `PJ-SMOKE-001` と記録内容が残る。
- [ ] 起動中の黒い画面を閉じると、そのURLを再読み込みしても接続できなくなる。

## 11. 多重タブの警告を試す（任意）

同時編集ができないことの警告が働くかを確かめます。

1. ツールを開いたまま、同じURLをもう1つのタブで開きます。

- [ ] 両方のタブに「同じデータを別のタブでも開いています」という警告が表示される。
- [ ] 片方のタブを閉じると、残ったタブの警告が消える。

## 結果記録

| 判定 | 条件 |
| ---- | ---- |
| OK | 必須項目がすべて期待どおりで、操作不能・データ消失・説明できないエラーがない |
| 条件付きOK | 軽微な表示上の違いだけで、保存・集計・復元には影響しない。違いを備考へ記録した |
| NG | 起動できない、保存や再読み込みで消える、計算が合わない、復元できない、操作不能になる |

| 項目 | 記録 |

| 最終判定 | OK / 条件付きOK / NG |
| 問題が起きた章・操作 |  |
| 画面に出たメッセージ |  |
| 実際に起きたこと |  |
| スクリーンショットの保存場所 |  |
| 備考 |  |

問題が起きた場合は、黒い画面とブラウザーの両方を閉じる前に、表示された文言とスクリーンショットを残してください。実在データを含むJSONは、GitHubのIssueなど公開の場所へ添付しないでください。
