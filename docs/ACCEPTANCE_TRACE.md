### 1.1 T-04 と T-16 を分けている理由

数字はどちらも「20分×3人＋30分×2人＝120分」で同じだが、確かめるものが違う。

- **T-04（A-05）**: 参加者変更を挟まず、作業時間へ参加人数を掛けた値が積み上がること。
- **T-16（A-16）**: 参加者を変更すると変更時刻で区間が分割され、前後が別々に計算されること。

T-16 だけでも数値は出るが、それは「分割が正しい」ことの結果である。掛け算そのものが壊れたときに落ちる試験を別に持つ。

## 4. 手動で確認する項目

自動化しない項目と、その確認方法を記す（実装計画8.2）。

| 対象 | 確認方法 | 実施記録 |
| ---- | -------- | -------- |
| 二分割レイアウト（12.1） | `--grep "@screenshot"` が `test-results/` へ主要幅の画像を出す。合否判定はせず目視する | 実施済み（2026-08-09、1024 / 1280 / 1440px）。1280・1440px で二分割、1024px で左ペインが上へ回り込み、いずれも横スクロールなし |
| 配布ZIPの展開（14章） | `npm run dist` の出力ZIPを展開し、静的配信して起動する | ZIPの展開のみ未実施。展開後の内容と同一のディレクトリに対する起動・保存・エクスポートは `distribution.spec.js` が自動で確認する |

当初は保存失敗の表示（9.1）も手動確認としていたが、状態を渡すだけで再現できるため `statusBar.test.js` で自動化した。実ブラウザでIndexedDBの書き込みを失敗させる手間に見合う情報は増えない。

狭い画面（1024px）での崩壊回避とキーボード操作も自動化したため、手動確認の対象から外した。
