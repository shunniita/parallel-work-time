## 0. 本書の位置づけ

Step 11 の実装で、**仕様が直接には決めていない点**と、**実装が選んだ点**を記録する。仕様の記述をそのまま写すことはしない。

## 1. 警告領域（8.8.1、8.8.2、12.2）

### 1.1 未終了区間は状態で絞らない

**決定: 警告領域の未終了区間一覧は、転記済み・アーカイブ済みの実施回も対象にする。**

通常の操作では閲覧のみの実施回に未終了区間は残らない（8.9.6 が集計済みへの遷移を塞ぐ）。しかし取り込んだJSONには存在しうる。警告領域は「気づかれていない記録」を見せる場所なので、状態を理由に隠さない。該当する行には「閲覧のみの実施回」と添える。

### 1.2 1分ごとの再評価は部分更新で行う

しきい値の判定は現在日時に依存するため、`main.js` が1分ごと（`THRESHOLD_RECHECK_INTERVAL_MS`）に警告領域の `tick()` を呼ぶ。

**決定: tick は `replaceChildren` を使わず、経過時間の文字列・超過の強調・件数見出しだけを書き換える。**

全再描画すると、警告領域内のリンクへフォーカスしていた利用者が毎分フォーカスを失う（`store.js` の規約3、`dom.js` の部分更新の道具はこのために既設）。未終了区間の集合そのものは保存を伴う操作でしか変わらず、その場合はストア購読で `render()` が呼ばれる。tick 側でも集合の異同は検査し、変わっていれば描き直す（別タブの保存を読み直した直後など）。

見出しの件数（「しきい値超過 n件」）も tick の更新対象である。実装時、行だけ更新して見出しを取り残す誤りを E2E が実際に検出した。

### 1.3 再評価タイマーはストアを通さない

`store.setState()` を1分ごとに呼ぶ設計は採らない。全画面の再描画になり、記入途中のフォームやフォーカスが毎分失われる。時刻の経過で変わる表示は警告領域だけなので、タイマーは警告領域の `tick()` に直結する。

### 1.4 経過時間の表示

「経過 2時間30分」の形とし、開始が現在より後（未来開始の手動追加・取り込みデータ）でも負を出さず0分とする。残り時間ではなく経過時間なので、切り捨てで数える。

## 2. 多重タブの検知（8.10）

### 2.1 名乗り合いの手順

`BroadcastChannel`（チャンネル名は `config.js` の `TAB_CHANNEL_NAME`）で次の3種をやり取りする。

| 便り | 意味 |
| ---- | ---- |
| `hello` | 起動した。全員へ名乗る |
| `ack` | `hello` への返事。後から開いたタブが先行タブを知る唯一の手段 |
| `bye` | 閉じる（`pagehide`） |

タブごとに乱数IDを持ち、自分の便りは数えない。相手が1つでもいれば、仕様書8.10 が定める文言をそのまま警告領域へ出す。

### 2.2 クラッシュしたタブの扱い

`bye` を送れずに消えたタブのぶんは警告が残る。**過剰に警告する方向の誤りであり、同時操作を見逃す方向ではないため許容する。** ハートビートで生存確認する設計は、常時タイマーを増やす割に防げる実害がない。再読み込みすれば作り直される。

### 2.3 ロックはしない

仕様書8.10 が「技術的に強制終了またはロックする必要はない」と明示している。警告を出すだけで、操作は塞がない。

## 3. 保存接続の管理（レビュー指摘 C-13）

### 3.1 並行 initialize の合流

`initialize()` の「`db === null` 確認 → `await` で開く」の間に別の呼び出しが入ると、データベースを二重に開き、片方の接続が閉じられずに残る。開きかけの Promise を持ち、並行呼び出しはそこへ合流させる。

### 3.2 `onversionchange` で自分から閉じる

将来 DB 版を上げる改訂を配布したとき、旧版のまま開きっぱなしのタブがあると、新しいタブの upgrade が永久にブロックされる。`onversionchange` を受けたら自分の接続を閉じ、以後の操作は「別のタブがデータベースを更新したため、この接続は閉じられました。再読み込みしてください。」で拒む。

修正前のこの症状は、契約テストが実際にタイムアウトで再現した（版2で開く2つ目の接続が `onsuccess` へ進めない）。

## 4. キーボード操作（13章、レビュー指摘 D-18）

### 4.1 ツリーは ARIA の tree パターンに従う

`role="tree"` / `role="group"` / `role="treeitem"` を付け、ノード間は矢印キーで移動する（↑↓移動、→展開・最初の子、←折りたたみ・親、Home/End）。

**Tab はツリー全体を1つの停留所として扱う（roving tabindex）。** 案件20件・実施回100件の規模では、Tab 移動だと詳細ペインへ抜けるまでに百回押すことになる。折りたたみボタン（▼/▶）も Tab の停留所から外す。矢印キーが同じ役割を持つためで、マウス操作は従来どおり残す。

展開・折りたたみは再描画を伴うため、直前のノードへフォーカスを戻す。戻さないと矢印キーを1回押すたびにフォーカスが body へ飛ぶ。

### 4.2 状態記号は読み上げ名で補う

ツリーの状態記号（●/○/◐/✓）は支援技術へ渡らないため、作業項目ノードの `aria-label` に語（作業中・未着手など）を含め、記号そのものは `aria-hidden` にする。

### 4.3 保存成否の読み上げ

ステータスバーの保存成否表示へ `role="status"` と `aria-live="polite"` を付けた（9.1）。失敗に気づけないと記録の欠落につながるため、画面を見ていない利用者にも届ける。

### 4.4 ナビゲーションの無効化コードを削除

仕様書12.2 の7画面がすべて実装されたため、「未実装の画面は押せない」分岐（D-18 の (d) が指摘した `disabled`）は削除した。

## 5. 起動時・実行時の異常の可視化（レビュー指摘 F-29）

- サンプルテンプレートの読込失敗は、**テンプレートが1件も無い場合に限り**警告領域へ出す。既にデータのある環境では初期投入自体が走らないため、毎回警告するのは雑音になる。
- `window.onerror` / `unhandledrejection` の受け皿を追加し、捕捉されなかった例外を警告領域へ1行で出す（同文は重ねない）。ブート前の失敗は従来どおり `renderBootFailure` が受ける。
