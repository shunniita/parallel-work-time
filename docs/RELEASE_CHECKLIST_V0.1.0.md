## 6. GitHub公開手順

実施順は「公開して問題ないことの確定 → public化 → 外部からの確認 → タグ → Release」とする。タグとReleaseを先に作っても、非公開のうちは対象者しか取得できない。逆に、public化はGit履歴を含むリポジトリ全体を一度に公開する操作であり、後戻りできない。

- [x] 必要な変更をレビューし、`main`へ統合する。
- [ ] `main`の公開予定コミットがクリーンで、全検証を通過していることを確認する。
- [ ] 実ブラウザーのクリーンプロファイルsmoke（4章）を終える。
- [ ] 履歴上の作者識別子を正しい1つへ揃える（1章）。public化後は書き換えの費用が跳ね上がるため、ここが最後の機会である。
- [ ] 非公開リポジトリを公開へ変更する。履歴・作者メール・秘密情報の最終承認後に行う。
- [ ] ログアウト状態で、リポジトリトップ・README・LICENSE・Actionsログに公開したくない内容がないことを確認する。
- [ ] Description と Topics を設定する。
- [ ] Dependabot alerts、secret scanning、push protection、code scanning を有効にする（3章）。
- [ ] `main` へ force push 禁止・ブランチ削除禁止・CIのstatus check必須を設定する。
- [ ] 公開予定コミットから最終ZIPを生成する（`npm run dist` が `SHA256SUMS.txt` も出す）。
- [ ] 公開予定コミットへ `v0.1.0` タグを付ける。
- [ ] GitHub ReleaseをDraftで作成する。
- [ ] `parallel-work-time.zip` と `SHA256SUMS.txt` を添付する。
- [ ] リリースノートに、対応環境、起動方法、平文保存、既知の制限、バックアップ方法を記載する。
- [ ] Draftを公開し、Release URLと公開日時を下記の記録欄へ残す。
- [ ] 公開後にZIPを第三者視点で再ダウンロードし、ハッシュと起動を確認する。
- [ ] READMEの「初回リリース」を完了状態へ更新する。
