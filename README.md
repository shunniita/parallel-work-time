# 同時並行作業時間計測支援ツール

複数の案件、作業項目、参加者が同時並行で作業する状況において、項目ごとの工数を記録・集計するためのブラウザアプリケーションです。

作業の開始・終了時刻、休憩時間、参加者数から工数を計算できます。時刻を記録できなかった作業については、工数を直接追加することもできます。

仕様書に定めた初版の機能はすべて実装済みです。ただし実運用データでの検証は行っていません（架空データのみで試験しています）。

## ダウンロードとインストール

GitHubに慣れていない方は、次の順番で配布用ZIPをダウンロードしてください。

1. このリポジトリ画面の右側にある **「Releases（リリース）」** を押します。画面幅によっては右側に表示されないことがあるため、その場合はページの下の方までスクロールして探すか、[Releasesページ](https://github.com/shunniita/parallel-work-time/releases)を直接開きます。
2. 一番新しいリリースを開きます。
3. リリースの **「Assets」** 欄にある `parallel-work-time.zip` を押してダウンロードします。
4. ダウンロードフォルダーにある `parallel-work-time.zip` を右クリックし、**「すべて展開」**を選びます。
5. 展開された `parallel-work-time` フォルダーを開き、`start-local.cmd` をダブルクリックします。
6. 黒い画面を閉じずに、開いたブラウザーで操作します。

> **`Source code (zip)` や `Source code (tar.gz)` は選ばないでください。** これらはGitHubが自動で用意する開発者向けのソース一式で、利用者向けの起動準備を確認した配布ZIPとは別物です。Releasesページに `parallel-work-time.zip` が無い場合は、まだ配布版が公開されていません。
>
> ZIPの中から `start-local.cmd` を直接開かず、必ず「すべて展開」したフォルダーから起動してください。Python、Node.js、管理者権限の追加は不要です。

## 想定する用途

一般的な時間計測ツールは、一人が一つの作業を順番に進める運用を想定していることがあります。

本ツールは、次のような状況を扱うことを目的としています。

* 複数の案件が同時に進行する
* 一つの案件に複数の作業項目がある
* 複数人が同じ作業項目へ参加する
* 作業中に参加者が増減する
* 作業と休憩を複数回繰り返す
* 一つの案件を複数回に分けて実施する
* 作業終了後に、項目ごとの合計工数を確認したい
* 別の記録システムへ転記する値を算出したい

## 主な機能

初版では、次の機能を実装しています。

* 案件IDごとの作業管理
* 同一案件に対する複数の実施回
* 対象種別とバリエーションに応じた作業項目の自動生成
* 複数の作業項目の同時進行
* 作業開始、休憩、再開、終了の記録
* 一つの作業区間への複数参加者の登録
* 作業中の参加者変更（変更時刻で区間を分割）
* 工数の直接入力
* 秒単位での工数計算
* 項目別合計工数の分単位への切り上げ
* 未終了区間の警告
* 集計値の転記済み管理
* JSON形式でのバックアップと復元
* 転記済みデータのアーカイブ

詳細は[仕様書](docs/同時並行作業時間計測支援ツール_仕様書.md)を参照してください。

## 工数の計算

作業区間の工数は「経過秒数 × 参加者数」、直接入力は人数を掛けない総工数として扱い、転記値は作業項目の合計秒を分単位へ一度だけ切り上げます（`ceil(合計秒 ÷ 60)`）。休憩区間は工数に含めません。

計算規則の詳細と例は[操作ガイド](manual/02-guide.md)を参照してください。

## 動作環境

正式な対応環境は次のとおりです。

| 区分 | 対応範囲 |
| ---- | -------- |
| OS | Windows 11（Windows 10も同等に動作する想定ですが、確認していません） |
| ブラウザー | Chrome、Edge、Firefox の各最新版 |
| 配信方式 | HTTPまたはHTTPSによる静的ファイル配信 |
| 必要な機能 | JavaScript、IndexedDB、BroadcastChannel |
| 画面幅 | 1024px以上 |

macOSとLinuxは、試験環境を用意できないため公式の対応対象としません。WSL上での利用も同様です。動作する可能性はありますが、確認していません。

自動試験はWindows上で実行しています。常用の回帰試験はChromium（ChromeとEdgeが共有）で、Firefoxは対応表明の裏づけとして同じE2E一式を通しています。

`file://`でHTMLファイルを直接開く方式は、動作保証の対象外です。IndexedDBとサンプルテンプレートの読み込みがブラウザーの制約で失敗します。

サーバー側のAPI、データベース、常駐プログラムは使用しません。

## データの保存

作業データはブラウザのIndexedDBへ保存します。

IndexedDBのデータは、利用する端末、ブラウザ、ブラウザプロファイル、配信元URLごとに分離されます。

次の場合、データを参照できなくなったり、失ったりする可能性があります。

* 別のPCやブラウザを使用した
* 配信元URLを変更した
* ブラウザのサイトデータを削除した
* ブラウザプロファイルを初期化した

重要なデータは、定期的にJSON形式でエクスポートしてください（仕様書9.5）。頻度は利用者が決めてください。毎日の実施を必須とはしません。

設定・バックアップ画面に最終エクスポート日時を表示します。エクスポートしたJSONは同じ版のツールへ取り込めます（設定画面の「JSONインポート」）。取り込みは全置換であり、取り込む前に現在のデータを退避できます。

### 保存内容は暗号化しません

IndexedDBの内容も、エクスポートするJSONも平文です。パスワードによる保護や暗号化の機能はありません。次の点に注意してください。

* 同じ端末とブラウザープロファイルを使える人は、開発者ツールから保存内容を読めます。
* エクスポートしたJSONは、そのまま読める形式のファイルです。保管場所と共有範囲は利用者が管理してください。
* 個人情報や機微な情報は入力しないでください。参加者名は識別できる範囲で最小限にすることを推奨します。
* 共有端末で使う場合は、作業後にJSONへ退避したうえで、ブラウザーのサイトデータを削除してください。

### 取り込むJSONは利用者本人が管理するものに限ります

インポートは、本ツールがエクスポートしたJSON、または利用者本人が内容を把握しているJSONだけを対象とします。第三者から受け取ったJSONの取り込みは想定していません。

取り込み時には構造・業務整合性・規模の検証を行い、通らないものは場所を添えて拒否します。ファイルサイズ、件数、文字列長（識別子を含む）、参加者数、数量、そして計算後の合計工数に上限を設けています。ただしこれは誤ったデータの取り込みを防ぐためのものであり、悪意ある入力に対する防御を保証するものではありません。

### 転記値を表計算ソフトへ貼り付けるとき

外部項目コードは自由入力です。`=`、`+`、`-`、`@` で始まる文字列を表計算ソフトのセルへ貼り付けると、数式として解釈されることがあります。転記値をコピーして使う場合は、貼り付け先で「テキストとして貼り付け」を選ぶか、外部項目コードにこれらの文字を先頭へ使わないでください。

開発には次のツールを使用します。

* Visual Studio Code

## 開発環境の準備

Node.jsはmiseを使用して管理します。使用する版は`mise.toml`が指定します（Node.js 24系）。`package.json`の`engines`にも同じ下限を書いてあり、mise以外で用意した場合でも版違いに気づけます。

```powershell
mise install
mise current
node --version
npm --version
```

開発時のコマンドは`mise exec --`を付けて実行します。付けずに実行すると、環境に残っている別の版のNode.jsを拾うことがあります。

## ローカルでの起動

ここはソースから開発する人向けの手順です。`file://`での直接起動は動作保証の対象外なので、開発用の静的配信サーバーを使用してください。Node.jsの標準モジュールのみで動作し、この開発用サーバー自体は配布物へ含めません。配布ZIPを利用する方は、展開後に `start-local.cmd` をダブルクリックしてください（Python・Node.js不要）。

```powershell
mise exec -- npm run serve
```

起動後、ブラウザで`http://127.0.0.1:4173/`を開きます。ポートは`--port`または環境変数`PORT`で変更できます。

```powershell
mise exec -- node tools/static-server.mjs --port 8080
```

初回起動時に架空のサンプルテンプレートが投入されます。仕様書12.2 の7画面（案件・実施回一覧、案件・実施回登録、作業項目詳細、集計・転記、作業テンプレート、アーカイブ、設定・バックアップ）がすべて操作できます。

データを初期状態へ戻したい場合は、ブラウザの開発者ツールから`parallel-work-time`データベースを削除して再読み込みしてください。

## テスト

テストツールは開発時のみ使用します。アプリケーション本体はビルド不要のままで、配布物へテストツールを含めません。

```powershell
mise exec -- npm install
mise exec -- npm test
```

`npm test`は単体テストと結合テストを実行します。計算処理（工数、丸め、状態判定、並び順）は`src/domain`の純関数へ閉じ込め、単体テストで固定しています。保存処理は`IndexedDbAdapter`と`MemoryAdapter`の両方へ同一の契約テストを通しています。

受入試験（E2E）はPlaywrightで実行します。初回のみブラウザの取得が必要です。

```powershell
mise exec -- npx playwright install chromium
mise exec -- npm run test:e2e
```

E2Eは静的配信サーバーを自動起動し、`http://127.0.0.1:4173`に対して実行します。既定はChromiumです。ChromeとEdgeはChromiumを共有するため、常用の回帰試験はこの1種で回します。

Firefoxは別実装なので、対応表明の裏づけを取るときに明示的に実行します。

```powershell
mise exec -- npx playwright install firefox
mise exec -- npm run test:e2e:firefox
```

仕様書16章の受入試験T-01〜T-18 は、試験名の先頭へ試験IDを付けてあります。個別に実行する場合は`--grep`で絞れます。

```powershell
mise exec -- npx playwright test --project=chromium --grep "T-10"
```

レイアウトの目視確認用に、主要幅のスクリーンショットを取得できます。合否判定は行わず、`test-results`へ画像を出力するだけです。

```powershell
mise exec -- npx playwright test --project=chromium --grep "@screenshot"
```

説明書（`manual/`）のスクリーンショットは、UIを変更したときに次のコマンドで撮り直し、変更をコミットします。出力先は `manual/images/`（Git管理下）です。

```powershell
mise exec -- npm run shots:manual
```

## 性能

仕様書13章の性能目標は「案件20件、実施回100件、作業区間2,000件程度で通常操作に支障がないこと」です。これを超える規模の保証は行いません。

目標規模のデータを投入して実測した値は次のとおりです。

| 操作 | 測定した対象 | 実測値 |
| ---- | ------------ | ------ |
| 起動（全件読み込み＋左ツリー描画） | 案件20件・実施回100件・区間2,000件の全件 | 約144ms |
| 実施回の集計表示 | 区間2,000件を持つ実施回1件 | 約53ms |
| JSONエクスポート | 上記全件 | 約58ms |

集計は選択中の実施回だけを対象とするため、区間2,000件を1つの実施回へ集中させて測っています。区間を100実施回へ均等に配ると、測る対象は1実施回あたり20区間になり、目標規模の集計性能を表しません。

測定環境は Windows 11、Node.js 24.18.0、Chromium（Playwright同梱版）です。測定は`tests/e2e/performance.spec.js`が行い、実行するたびに値を出力します。

```powershell
mise exec -- npx playwright test --project=chromium --grep "性能目標"
```

データは起動時に全件をメモリへ読み込みます（`loadAll()`）。目標規模では問題ありませんが、桁が変わる規模では起動が遅くなります。

## 配布

ビルド工程はありません。配布物へ含めるのは次のファイルとディレクトリだけです。

```text
start-local.cmd
local-settings.txt
LICENSE
README.md
manual/
アプリ内部（変更しないでください）/
├─ _local-server.ps1
├─ index.html
├─ src/
├─ data/
└─ licenses/
```

`tools/`、`tests/`、`docs/`、`node_modules/`、`package.json`は配布物へ含めません。開発時にだけ使います。

ZIP直下の `README.md` は利用者向けの `distribution/README.md` からコピーします。開発環境のルート `README.md` とは分け、配布後の相対リンクと案内順を利用者向けに保ちます。

```powershell
mise exec -- npm run dist
```

次の3つが作られます。

| 生成物 | 内容 |
| ------ | ---- |
| `dist/parallel-work-time.zip` | 配布するZIP |
| `dist/parallel-work-time/` | ZIPと同じ内容を展開した状態 |
| `dist/manifest.json` | 収録した全ファイルの相対パス・バイト数・SHA-256 |

ZIPはNodeの標準機能だけで作ります。外部の圧縮コマンドを使わないため、コマンドの有無で結果が変わりません。同じコミットからは常に同じバイト列になるので、配布物のSHA-256を公開して照合できます。ZIPを書いた直後に読み直してマニフェストと照合し、一致しなければ非0で終了します。

`--stage-only`を付けると、ZIPを作らずに`dist/parallel-work-time/`だけを揃えます。

### 展開後の起動

Windows 11では、ZIPを展開して `start-local.cmd` をダブルクリックします。Windows標準のPowerShellだけを使って `127.0.0.1:4173` へ配信し、ブラウザーを開きます。Python、Node.js、管理者権限は不要です。利用中は開いたコマンド画面を閉じないでください。

既定ポートを変更する場合は、起動前に `local-settings.txt` の `port=4173` の数字だけを `1024`〜`65535` の範囲で編集します。指定値は次回以降も維持され、使用中でも別ポートへ自動変更しません。ポート変更はブラウザーの保存先URLも変えるため、変更前にJSONをエクスポートしてください。

組織のサーバーで共有する場合は、従来どおり任意の静的配信サーバーで `parallel-work-time/アプリ内部（変更しないでください）/` をHTTPまたはHTTPS配信できます（仕様書5.1.3）。配布ZIPには開発用の `tools/` は含めません。

ソースを取得している場合は、付属サーバーで展開先を配信して確認できます。

```powershell
mise exec -- node tools/static-server.mjs --root "dist/parallel-work-time/アプリ内部（変更しないでください）"
```

## 開発方針

* 仕様書に記載された機能を優先する
* 初版では一人の管理者による利用を前提とする
* 複数利用者の同時編集には対応しない
* 外部APIや外部クラウドサービスへデータを送信しない
* 不要な外部ライブラリを導入しない
* 仕様変更は文書へ反映してから実装する
* 実データを使用せず、架空データで試験する
